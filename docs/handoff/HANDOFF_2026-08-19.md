## 2. O defeito, medido — não suposto

`git ls-files -s BACKLOG.md` devolve o MESMO hash de blob antes e depois de editar o arquivo **sem**
`git add` (reproduzido ao vivo). Isso é esperado — `ls-files -s` lê o ÍNDICE do git, não o disco. O
selo (`selar-arvore.mjs`) parecia coberto disso porque também varre `git status --porcelain -uall`
(que lista arquivos modificados, não só novos) — mas hashava esses dois grupos de formas
DIFERENTES: bytes crus do disco (CRLF, com `core.autocrlf=true`) para o que está só modificado; hash
de blob do índice (LF, normalizado pelo git) para o que já está staged ou commitado.

**O fluxo padrão deste projeto** — `npm run gate` (termina em `selo:gravar`) ANTES de `git add` —
garante que quase todo arquivo tocado numa sessão passa por essa transição entre o `--gravar` e o
`--conferir` seguinte: editado → hash CRLF → `git add` + commit → agora staged → hash LF. **Zero
bytes de diferença real, e o selo gritava "árvore mudou" mesmo assim.**

**Por que sobreviveu sem ninguém notar:** `selar-arvore.mjs` nasceu em 05/08/2026 sem autoteste — a
única trava deste projeto nessa condição, contra a regra do próprio método (*"toda trava nova nasce
com autoteste, no mesmo commit"*). E o remédio que a própria mensagem de erro prescreve — "rode o
gate de novo" — é indistinguível, de fora, de disciplina normal: ninguém tinha motivo para suspeitar
que o aviso era falso.

## 3. O conserto

`impressao()` reescrita para ler **sempre o disco**, nunca o índice: `git ls-files` só lista os
CAMINHOS rastreados; cada um (rastreado ou presente no `status`) é lido com `readFileSync` e
hashado. Arquivo rastreado que sumiu do disco vira `AUSENTE` explícito, não é pulado em silêncio.

**`scripts/autoteste-selar-arvore.mjs` (novo)** — 6 casos, num repositório git de mentira montado a
cada rodada:

| Caso | O que prova |
|---|---|
| A | árvore limpa, gravar→conferir → OK |
| B | mutação real depois de gravar → ACUSA |
| **C** | 🔴 **o próprio defeito, reproduzido**: mesmo conteúdo, só staged depois de gravar → NÃO acusa |
| D | arquivo novo não rastreado → ACUSA |
| E | arquivo rastreado apagado do disco → ACUSA |
| F | nunca gravou selo → recusa com a mensagem certa |

Achado no caminho da primeira versão do próprio teste: sem `.gitignore` no repositório de mentira, o
arquivo do selo (`node_modules/.selo-do-gate`) virava "não rastreado" e contaminava a MEDIÇÃO
SEGUINTE — corrigido com um `.gitignore` no repositório de teste, igual ao projeto real.
