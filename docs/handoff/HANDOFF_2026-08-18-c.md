## 2. S-060 — a trilha genérica

**A pergunta:** *"talvez seja necessário criarmos um novo GitHub, uma nova pasta (…) fazemos as
implementações e testes, e mesclaríamos com produção somente o que escolhêssemos. Dá pra fazer
assim?"*

**A resposta, medida antes de prometida:** não precisa de repositório novo. Dois fatos já
garantiam isso — `npm run generico` (portão do §0) já prova que `src/` e `index.html` não têm texto
de cliente cravado, e `publicar.yml` sobe a pasta `docs/` **inteira**, não um arquivo. Faltava um
segundo caminho para o `fetch` de `carregar.ts` encontrar um segundo conjunto de dados.

Duas perguntas de acompanhamento, respondidas antes de construir:

- **"Qual URL eu vou verificar?"** → `https://flaviocom.github.io/escala-porteiros/generico/` —
  confirmado com `vite preview --mode generico`, que já serve exatamente nesse caminho.
- **"Isso não vai ser conflitante?"** → não, porque `src/dominio/` já é ilha (portão `arquitetura`)
  — mas corrigi uma imprecisão minha: "sem pasta nova" estava errado, nascem pastas (`docs/generico/`,
  `public-generico/`), só não repositório novo.

### O que foi construído

1. **`vite.config.ts`** — `defineConfig(({mode}) => …)`: `base`, `publicDir`, `outDir` alternam por
   `mode === 'generico'` (`vite build --mode generico`, script `npm run build:generico`). Zero linha
   de `src/` muda entre os dois builds.
2. **`public-generico/dados/{config,pessoas,blocos}.json`** — identidade neutra: "Escala de
   plantões", "Demonstração — portaria de prédio" (o próprio exemplo que `src/dominio/tipos.ts` já
   citava), vocabulário "Plantonista"/"plantonistas", sem Santa Ceia, 3 pessoas fictícias, um bloco
   de 1 semana (7 turnos) para a demonstração abrir com conteúdo, não vazia.
3. **`scripts/conferir-generico-dados.mjs`** (portão) + **`scripts/autoteste-conferir-generico-dados.mjs`**
   (6 casos) — varre `public-generico/` e `docs/generico/` pelos mesmos termos do `portao-generico.mjs`.
   🔴 **Achado no caminho:** a guarda de "módulo principal" (`import.meta.url === file://${argv[1]}`)
   falhava em silêncio no Windows — barra invertida em `process.argv[1]` contra barra normal em
   `import.meta.url`, então o portão nunca entrava no bloco de execução e sempre saía OK sem medir
   nada. Removida a guarda (os outros portões deste projeto nunca a tiveram, por isso nunca pegaram
   esse defeito).
4. **Gate: 33 → 36 passos.** `generico:dados:autoteste` entrou como 16º (junto dos outros autotestes
   de escopo, roda antes do build existir); `build:generico` e `generico:dados` entraram como
   31º/32º (depois de `build`). `docs/PORTOES.md` e `docs/OPERACAO.md` renumerados, com seção
   própria escrita para os 3 passos novos — não só o número.
5. **Verificado num navegador de verdade**, não só por portão: `vite preview --mode generico` +
   Playwright, screenshot da tela renderizada. "ESCALA DE PLANTÕES · Demonstração — portaria de
   prédio", "Plantonista 1/2/3" nos sete dias do bloco de exemplo, filtro dizendo "Plantonista".
   Vocabulário neutro provado ponta a ponta.
6. **`docs/ARQUITETURA.md`** ganhou a seção "A segunda trilha" (o mecanismo completo, a tabela
   base/publicDir/outDir, os limites declarados — isto não é multi-tenant). **`docs/FASE2.md`**
   ganhou **§P4.w2**, ligando a trilha ao que ela destrava (iterar o P4.w sem risco à produção) e ao
   que ainda falta (as features do P4.w em si — a trilha é o palco, não a peça).
7. **`docs/capacidades.json`** ganhou as 2 folhas novas. **`docs/LEMBRETE_WHATSAPP.md`** e
   `AGENTS.md` (linha de roteamento) atualizados.

## 5. Como reverter

`git revert` do commit desta entrada. `docs/generico/` some do próximo deploy (o build não se
regenera sozinho publicado — reverter aqui só afeta o próximo push); os 2 scripts novos,
`public-generico/`, e as seções de `ARQUITETURA.md`/`FASE2.md` somem; `package.json`/`vite.config.ts`
voltam à forma anterior; o gate volta a 33 passos. Produção: **nenhuma linha de `src/` foi tocada**
— zero risco ao site que os irmãos usam.
