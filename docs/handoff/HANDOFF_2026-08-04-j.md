## A solicitação, e por que ela é uma correção de rumo

> *"Você não me disse se resolveu a questão do token para entrar na área administrativa ou não. Não
> houve uma maneira concreta de preparar o login via GitHub. Publicar na tela tem que estar
> habilitado. É a funcionalidade principal."*

Ele está certo, e o diagnóstico é sobre **como eu entreguei**, não sobre o que faltava construir.

Eu tinha: explicado quatro opções, recomendado uma, e deixado um `.cmd` na Área de Trabalho. Três
problemas nisso:

1. **O guia morava longe de onde a pergunta aparece.** Quem trava, trava na tela de primeiro acesso —
   e a instrução estava num arquivo noutro lugar.
2. **O `.cmd` nunca foi rodado por mim.** Entreguei um artefato não verificado e chamei de caminho
   preparado.
3. **A mensagem de recusa não dizia o que consertar** — e é exatamente aí que a pessoa desiste.

## O que mudou

### 1. O passo a passo está NA TELA

Bloco **"Não tenho token — como criar (3 minutos)"**, na própria tela de primeiro acesso: um botão
que abre a página certa do GitHub e os quatro campos com o valor exato.

| Campo | Valor |
|---|---|
| Token name | `escala-porteiros` |
| Expiration | 1 year (ou o que preferir) |
| Repository access | **Only select repositories** → `escala-porteiros` |
| Permissions | Repository permissions → **Contents: Read and write** |

### 2. Uma fonte só para o que marcar e o que exigir

Os valores vêm de `COMO_CRIAR_O_TOKEN`, **no mesmo arquivo** que confere o token. A tela e o
verificador leem da mesma constante — e há teste provando que não divergem. Guia que envelhece
separado do código vira instrução errada com cara de certa.

### 3. 🔴 Cada recusa nomeia o campo a corrigir

As mensagens eram genéricas: *"O GitHub recusou o token (HTTP 404)"*.

**E 404 é a resposta mais traiçoeira que existe aqui.** Num token *fine-grained*, **repositório não
marcado** volta como *não encontrado* — não como *sem permissão*. Quem lê "404" procura erro de
digitação, e o problema está numa caixa de seleção da outra página.

| Resposta | O que a tela diz agora |
|---|---|
| 401 | confira se copiou o valor **inteiro** — ele aparece uma única vez |
| 404 | o token **não enxerga** `escala-porteiros`; em *Repository access*, escolha *Only select repositories* e marque o repositório |
| sem escrita | em *Repository permissions*, ponha **Contents** em *Read and write* |
| rede fora | não deu para falar com o GitHub — confira a conexão |

### 4. O `.cmd` virou o que ele faz bem

Abrir a tela. O guia não mora mais nele — e assim não há duas versões da instrução para divergirem.

## Os portões

**7 testes** em `src/admin/github.test.ts`: cada recusa nomeia o campo (401, 404, sem escrita, rede
fora), a outra ponta aceita o token bom, e — o que impede a divergência — **o guia manda marcar
exatamente o que o verificador cobra**.

Conferido ao vivo na tela publicada: o bloco abre, os quatro textos-chave aparecem, o link abre em
nova aba com alvo de toque de 296×44.

E a URL foi **conferida, não suposta**: `settings/personal-access-tokens/new` existe e pede login —
porque a sessão é dele, não minha.
