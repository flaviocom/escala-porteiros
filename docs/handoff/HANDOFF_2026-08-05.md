## A solicitação

> *"Eu não consigo logar no site administrativo porque pede, além de senha, token do GitHub. Eu não
> tenho token. Quais são as opções para que eu entre sem digitar token?"*

E, logo depois:

> *"Se eu entrar com o token uma única vez, não fica liberado? Eu quero deixar liberado."*

## Antes de tudo: a escala no site estava certa

O Flavio lembrou que eu havia reportado erro na escala, e que **esse é o motivo do site existir**.
Conferido ao vivo, no site publicado, dado contra tela: **131 de 131 dias, 543 nomes, 0
divergências**, o 16/08 aparecendo como SANTA CEIA sem ninguém, console limpo.

⚠️ **Foi falha minha de clareza no relato anterior:** o defeito é no **site antigo**
(`escala-irmaos-2026-mar`), que escala seis irmãos no dia da Ceia porque a data mora no código dele.
Dizer "a escala está com erro" sem dizer **qual site** fez o dono achar que o produto novo estava
quebrado. Nome do sistema junto com o defeito, sempre.

## 🔴 O defeito: a tela cobrava senha para proteger o vazio

O token já era opcional desde a véspera. Mas a tela continuava exigindo **senha** — e é aí que estava
o erro de desenho, que só apareceu porque o dono reclamou duas vezes.

A senha existe por **um** motivo: cifrar o token no `localStorage`. Sem token e sem chave do motor, o
cofre é um objeto **vazio** — e a tela pedia oito caracteres para proteger nada.

Pior: o pedágio nem sigilo comprava. O repositório é **público**, os dados são públicos. Aquela senha
protegia apenas o token, que ali não existia.

**Quem só queria entrar e olhar a escala pagava um pedágio inventado.**

### O conserto

- **Botão no topo, sem campo nenhum:** *"Entrar agora — sem senha, sem token"*. Não grava cofre, não
  pede nada. Gera, valida, ajusta, baixa. Só *Publicar* fica de fora — e a tela ensina a subir o
  arquivo pelo GitHub com o login normal.
- **Os campos de senha só aparecem** quando há token ou chave do motor digitados. A proteção não
  sumiu: ficou **proporcional ao que existe para proteger**.
- Sumiu um botão duplicado que eu mesmo tinha acabado de criar — dois botões idênticos na mesma tela
  fazem a pessoa procurar a diferença que não existe.

## O segundo pedido: "entrou uma vez, fica liberado"

Metade já era verdade e a tela não dizia: o token **fica** guardado, cifrado, e **nunca mais é
pedido**. No retorno pede-se só a senha. Agora a tela afirma isso.

A outra metade era defeito meu: o campo de senha não tinha `name` nem `autocomplete`, e **sem isso o
Chrome nunca oferece "salvar senha"**. Ele digitava a senha em toda visita porque o navegador não
tinha como se oferecer para lembrá-la.

**A saída certa é o gerenciador de senhas — não guardar o token em claro.** O token segue cifrado;
quem passa a lembrar a senha é o navegador, que existe para isso e a guarda melhor do que qualquer
coisa que este site pudesse inventar. Nos campos de TOKEN e CHAVE DO MOTOR o valor é `off`: não são a
senha da pessoa, e oferecer salvá-los faria o navegador propor a senha errada no retorno.

## O portão

`npm run vivo:entrar` — **11 de 11**, provando **as duas pontas**:

- sem segredo: **0** campos de senha, entra num clique, e o `localStorage` fica **sem cofre**;
- com token digitado: os campos de senha **voltam** (0 → 2) e o botão passa a *"guardar com senha"*.

Provar só a primeira deixaria passar um conserto que abrisse o cofre para todo mundo.

### 🔴 E a régua nasceu errada

Contar `input[type="password"]` **media a coisa errada**: o campo do token e o da chave do motor
também são desse tipo. O portão acusou "2 campos de senha" numa tela que não tinha nenhum. Passou a
medir pelo **rótulo**. Sem isso, ele reprovaria o produto por defeito da própria régua — que é a
forma mais convincente de portão mentiroso, porque o vermelho parece um achado.

## O que ficou com o dono, e por quê

O token foi criado por ele. **Não digito, não leio da área de transferência, não transcrevo e não
cadastro o valor de credencial** — limite fixo do método, e não muda com autorização.

O que dá para fazer foi feito: a linha `GITHUB_PAT_ESCALA_PORTEIROS` já existia na central com a
descrição completa (escopo exato, onde gerar, onde o valor vive, e o aviso de **não** reaproveitar o
`GITHUB_PAT` amplo — aquele tem `delete_repo` e está pendente de rotação desde junho). Sobrou o
`Ctrl+V`, com o campo do site focado e o editor aberto na linha certa.

Descoberto no caminho, e a instrução da tela não mencionava: o GitHub exige **confirmação de
identidade por e-mail** (*sudo mode*) antes de deixar criar token. É o primeiro passo, e é onde
alguém sem prática trava.

## Sobre o escopo, que era a pergunta mais séria

> *"Os demais projetos que ficam lá no meu GitHub não podem estar visíveis neste site, correto?"*

Correto, e há **duas** travas independentes:

1. **Do GitHub:** um token *fine-grained* com "Only select repositories → escala-porteiros" não
   alcança nenhum outro repositório. Não é configuração do site — é o GitHub que recusa.
2. **Do código:** as **7** chamadas à API apontam para um repositório escrito fixo
   (`github.ts:17-18`). Não há um ponto sequer onde o nome do repositório seja montado
   dinamicamente. Mesmo com um token amplo colado por engano, este site não pede outra coisa.
